## 一、贪心阈值聚类（论文 Algorithm 3-2）

用于 Banner 文本聚类。**不需要指定簇数**，由阈值 θ 自动决定。

### 输入数据

假设采集了 5 条 SMTP banner，标准化后：

```
b1: "google.com ESMTP [RandomID] - gsmtp"          ← Gmail
b2: "outlook.com Microsoft ESMTP MAIL Service"     ← Outlook
b3: "google.com ESMTP [RandomID] - gsmtp"          ← Gmail（另一台服务器）
b4: "outlook.com Microsoft ESMTP MAIL Service"     ← Outlook（另一台服务器）
b5: "[DomainName] ESMTP Postfix"                    ← Postfix
```

### Step 1: 计算两两相似度矩阵

对每对文本计算综合相似度（论文公式 3-4）：

```
综合相似度 = 0.7 × SequenceMatcher(字符级) + 0.3 × TF-IDF余弦相似度(词级)
```

得到 5×5 对称矩阵：

|      | b1    | b2    | b3    | b4    | b5    |
|------|-------|-------|-------|-------|-------|
| **b1** | **1.00** | **0.10** | **0.95** | **0.10** | **0.15** |
| b2   | 0.10  | 1.00  | 0.10  | 0.92  | 0.20  |
| b3   | 0.95  | 0.10  | 1.00  | 0.10  | 0.15  |
| b4   | 0.10  | 0.92  | 0.10  | 1.00  | 0.20  |
| b5   | 0.15  | 0.20  | 0.15  | 0.20  | 1.00  |

观察：b1↔b3 = 0.95（同簇），b2↔b4 = 0.92（同簇），b1↔b2 = 0.10（不同簇）

### Step 2: 设置阈值 θ = 0.7

只合并相似度 ≥ 0.7 的样本。

### Step 3: 逐轮合并

#### 第 1 轮 — 以 b1 为中心

| 扫描 | 相似度 | ≥0.7? | 操作 |
|:----:|:-----:|:-----:|------|
| b2 | 0.10 | ❌ | 跳过 |
| **b3** | **0.95** | **✅** | **归入簇1** |
| b4 | 0.10 | ❌ | 跳过 |
| b5 | 0.15 | ❌ | 跳过 |

```
簇1 = {b1, b3}
```

#### 第 2 轮 — 下一个未分配的是 b2

| 扫描 | 相似度 | ≥0.7? | 操作 |
|:----:|:-----:|:-----:|------|
| **b4** | **0.92** | **✅** | **归入簇2** |
| b5 | 0.20 | ❌ | 跳过 |

```
簇2 = {b2, b4}
```

#### 第 3 轮 — 下一个未分配的是 b5

没有剩余未分配样本。

```
簇3 = {b5}
```

### 结果

| 簇 | 包含 | 中心模板 | 判定的厂商 |
|:--:|:----:|---------|:--------:|
| 1 | b1, b3 | `[DomainName] ESMTP [RandomID] - gsmtp` | Gmail |
| 2 | b2, b4 | `outlook.com Microsoft ESMTP MAIL Service` | Outlook |
| 3 | b5 | `[DomainName] ESMTP Postfix` | Postfix |

**3 个簇 = 3 个厂商，完全正确。**

### 阈值 θ 的影响

| θ | 簇数 | 结果 |
|:--:|:----:|------|
| 0.95 | 5 | 每个样本单独一簇，过细 |
| **0.70** | **3** | **恰好 3 个厂商** |
| 0.30 | 2 | b1/b3 和 b5 被合并，Postfix 和 Gmail 混在一起 |
| 0.10 | 1 | 全部合并，无区分度 |

## 二、K-Medoids 聚类（论文 3.2.3 节）

用于 Webmail 页面 DOM 序列聚类。**需要指定 K**（簇数），通过 Elbow 法确定。

### 用物理思想理解

把每个样本想象成一维数轴上的一个点，每个点的"质量"相同：

```
  样本:    A     B     C          D     E     F
  坐标:    1     2     3          8     9     10
          |-----|-----|----------|-----|-----|
           ← 簇1 →               ← 簇2 →
```

K-Medoids 要做的事情：**选 K 个样本作为"中心"，把所有点分配到最近的中心，使得总距离（势能）最小。**

就像在数轴上放 K 个"引力中心"，每个点被最近的中心吸引过去，系统的总势能 = 每个点到其中心的距离之和。

### 一维例子逐步骤

数轴上有 6 个点，坐标 [1, 2, 3, 8, 9, 10]，K=2。

肉眼一看就知道应该分 {1,2,3} 和 {8,9,10}，但算法怎么找到这个结果？

#### Step 1: 随机选初始中心

假设随机选到 B(2) 和 E(9)：

```
  中心:       B                    E
  坐标:       2                    9
          |-----|-----|----------|-----|-----|
             1     2     3      8     9     10
```

#### Step 2: 分配

每个点归到最近的中心：

| 样本 | 坐标 | 到 B(2) 距离 | 到 E(9) 距离 | 归到 |
|:----:|:---:|:----------:|:----------:|:---:|
| A | 1 | |1-2|=1 | |1-9|=8 | **簇B** |
| B | 2 | 0 | 7 | **簇B** |
| C | 3 | 1 | 6 | **簇B** |
| D | 8 | 6 | 1 | **簇E** |
| E | 9 | 7 | 0 | **簇E** |
| F | 10 | 8 | 1 | **簇E** |

```
第1轮分配结果:
  簇B = {A, B, C}   总势能 = 1 + 0 + 1 = 2
  簇E = {D, E, F}   总势能 = 1 + 0 + 1 = 2
  系统总势能 = 2 + 2 = 4
```

#### Step 3: 更新中心（找 medoid）

K-Medoids 的 medoid 必须是**实际存在的样本点**（不同于 K-Means 可以取虚拟均值点）。

对每个簇，尝试把每个成员作为新中心，选总势能最小的：

**簇B {A(1), B(2), C(3)}**：

| 候选 | 到 A 距离 | 到 B 距离 | 到 C 距离 | 总势能 |
|:----:|:---------:|:---------:|:---------:|:-----:|
| A(1) | 0 | 1 | 2 | **3** ✅ 最小 |
| B(2) | 1 | 0 | 1 | 2 |
| C(3) | 2 | 1 | 0 | 3 |

→ A(1) 总势能最小(3)，成为新 medoid

**簇E {D(8), E(9), F(10)}**：

| 候选 | 到 D 距离 | 到 E 距离 | 到 F 距离 | 总势能 |
|:----:|:---------:|:---------:|:---------:|:-----:|
| D(8) | 0 | 1 | 2 | **3** ✅ 最小 |
| E(9) | 1 | 0 | 1 | 2 |
| F(10)| 2 | 1 | 0 | 3 |

→ D(8) 总势能最小(3)，成为新 medoid

#### Step 4: 重新分配

新中心 A(1) 和 D(8)：

| 样本 | 到 A(1) 距离 | 到 D(8) 距离 | 归到 |
|:----:|:-----------:|:-----------:|:---:|
| A | 0 | 7 | **簇A** |
| B | 1 | 6 | **簇A** |
| C | 2 | 5 | **簇A** |
| D | 7 | 0 | **簇D** |
| E | 8 | 1 | **簇D** |
| F | 9 | 2 | **簇D** |

```
第2轮:
  簇A = {A, B, C}   总势能 = 0+1+2 = 3
  簇D = {D, E, F}   总势能 = 0+1+2 = 3
  系统总势能 = 6
```

#### Step 5: 再更新中心

**簇A**: A(1) 已经是最小势能的点，不变
**簇D**: D(8) 已经是最小势能的点，不变

中心不再变化 → **收敛**

### 最终结果

| 簇 | 样本 | Medoid | 势能 |
|:--:|:----:|:------:|:----:|
| 左 | A, B, C | A(1) | 3 |
| 右 | D, E, F | D(8) | 3 |

肉眼一看就对的分类：{1,2,3} 和 {8,9,10}。

### K-Medoids 的陷阱：一定会收敛到正确结果吗？

**不会。** K-Medoids 保证收敛，但只保证收敛到**局部最优**，不保证**全局最优**。

#### 具体例子

数轴上 6 个点：`[0, 1, 2, 4, 5, 6]`，K=2。

肉眼一看就知道正确答案：
```
左簇 = {0, 1, 2}  medoid=1  势能 = 1+0+1 = 2
右簇 = {4, 5, 6}  medoid=5  势能 = 1+0+1 = 2
总势能 = 4
```

但如果随机初始化选到了 0 和 6：

```
初始中心: 0 和 6

第1轮分配:
  0→0(0), 1→0(1), 2→0(2), 4→6(2), 5→6(1), 6→6(0)
  簇0 = {0, 1, 2, 4}, 簇1 = {5, 6}
                              ↑ 4 被误分到左簇！

第1轮更新 medoid:
  簇0 {0,1,2,4}: 候选2 总距离=8  ← 最小
  簇1 {5,6}:     候选5 总距离=1  ← 最小

第2轮分配 (中心=2 和 5):
  0→2(2,5), 1→2(1,4), 2→2(0,3), 4→2(2,1), 5→5(3,0), 6→5(4,1)
  簇0 = {0, 1, 2, 4}, 簇1 = {5, 6}
                                ↑ 4 到 2 和 5 距离相等！
                                  平局时通常分给簇0

第2轮更新 medoid: 不变 → 收敛
```

**结果：** `{0, 1, 2, 4}` 和 `{5, 6}`，总势能 = 8

```
最优解:  {0,1,2} + {4,5,6}  总势能 = 4  ← 全局最优
K-Medoids: {0,1,2,4} + {5,6}  总势能 = 8  ← 局部最优，差一倍！
```

### 为什么 K-Medoids 跳不出来？

因为 K-Medoids 只能选**实际样本**作为中心，而且每次更新只在**当前簇的成员**里选。

1. 第 1 轮把 4 错误地分配给了左簇
2. 左簇更新 medoid 时 2 胜出（在 {0,1,2,4} 中 2 确实是最优中心）
3. 第 2 轮 4 到 2 和到 5 的距离相等（都是 2），平局时通常归左簇
4. 收敛后 4 永远回不去右簇——因为 5/6 之间的距离是 1，4 到 5/6 的距离是 1 或 2，并不比 2 更有吸引力

**根本原因**：初始随机选择把 4 困在了错误的簇里，后续的 medoid 更新无法纠正这个错误。

### 怎么解决？

**多跑几次，取势能最小的。**

```python
best_potential = float('inf')
best_result = None
for seed in range(20):  # 随机重启 20 次
    clusters, medoids = kmedoids(texts, k=K, random_seed=seed)
    potential = compute_total_potential(texts, clusters, medoids)
    if potential < best_potential:
        best_potential = potential
        best_result = (clusters, medoids)
```

这就像做物理实验——系统可能卡在局部势能极小值，多从不同的初始状态开始，选势能最低的那个。

### K-Means 用均值作为中心，比如簇 {1,2,3} 的均值是 (1+2+3)/3 = 2.0。但 2.0 不是一个**实际存在的样本**。

K-Medoids 强制中心必须是**实际样本**——这对 DOM 序列这类数据很重要：
- DOM 序列的"均值"没有意义（`<div>` 和 `<table>` 怎么平均？）
- 必须用一条真实的 DOM 序列作为模板来匹配

### 扩展到 N 维

一维的"距离"是坐标差的绝对值 |x₁-x₂|。N 维就是欧氏距离或编辑距离。物理思想完全一样：

```
N 维空间的"势能" = Σ 每个点到其 medoid 的距离
K-Medoids 找到 K 个 medoid，使总势能最小
```

论文中的 DOM 标签序列经过 LZ78 压缩后变成数字编码序列，用编辑距离衡量"远近"，
本质上就是在高维空间里做 K-Medoids。

### 真实例子：DOM 序列聚类

### 与 K-Means 的区别

| | K-Means | K-Medoids |
|---|---|---|
| 中心 | 虚拟点（簇内均值） | 真实样本点 |
| 适用数据 | 数值向量 | 任意可计算距离的序列 |
| 对离群点 | 敏感 | 鲁棒 |
| 论文用途 | — | DOM 标签序列 |

### 输入数据

假设采集了 6 个 Webmail 页面的 DOM 标签序列（经过 LZ78 压缩后的编码序列）：

```
s0: [0, 0, 0, 4, 0, 6, 0, 0, 4, 0, 11, 11, 9, 0, 8]    ← Roundcube 服务器 A
s1: [0, 0, 4, 0, 6, 0, 0, 4, 0, 11, 9, 0, 8]           ← Roundcube 服务器 B
s2: [0, 0, 0, 0, 4, 0, 6, 0, 0, 4, 0, 11, 9, 0, 8]     ← Roundcube 服务器 C
s3: [1, 2, 1, 2, 3, 1, 2, 3, 4, 5]                       ← Zimbra 服务器 A
s4: [1, 2, 2, 1, 2, 3, 1, 2, 3, 4]                       ← Zimbra 服务器 B
s5: [7, 8, 7, 8, 7, 8, 9, 10]                            ← 自定义登录页
```

### Step 1: 计算距离矩阵

使用编辑距离（Levenshtein）：

```
dist(s0, s1) = 3（删除 2 个 0 和 1 个 11）
dist(s0, s2) = 1（插入 1 个 0）
dist(s0, s3) = 22（完全不同）
dist(s1, s4) = 19（完全不同）
dist(s3, s4) = 4（相似）
dist(s5, s0) = 18（完全不同）
...
```

得到 6×6 距离矩阵：

|       | s0  | s1  | s2  | s3  | s4  | s5  |
|-------|:---:|:---:|:---:|:---:|:---:|:---:|
| **s0** | 0   | **3**  | **1**  | 22  | 24  | 18  |
| s1   | 3   | 0   | 4   | 20  | 19  | 17  |
| s2   | 1   | 4   | 0   | 21  | 23  | 19  |
| s3   | 22  | 20  | 21  | 0   | **4**  | 15  |
| s4   | 24  | 19  | 23  | 4   | 0   | 14  |
| s5   | 18  | 17  | 19  | 15  | 14  | 0   |

观察：s0↔s1↔s2 距离小（同簇），s3↔s4 距离小（同簇），s5 和谁都远（离群）。

### Step 2: 选 K（Elbow 法）

论文先用 Elbow 法确定最佳 K。计算 K=1..6 的 WCSS（簇内平方和）：

```
K=1: WCSS = 1620
K=2: WCSS =  235  ← 下降率最大（83%），这是肘部
K=3: WCSS =  180
K=4: WCSS =  145
K=5: WCSS =  120
K=6: WCSS =  100
```

```
WCSS
1600 │*
     │
 800 │
     │
 235 │    *
 180 │        *
 145 │            *
 120 │                *
 100 │                    *
     └──────────────────────────→ K
     1   2   3   4   5   6
         ↑
       肘部 → K=2
```

推荐 K=2，因为从 1→2 的下降最陡。从数据看也确实应该分 2 簇（Roundcube + Zimbra），s5 被归入较近的一簇。

### Step 3: 初始化 medoids

随机选 2 个样本作为初始 medoids。假设随机选到 s1 和 s4：

```
Medoid 1 = s1
Medoid 2 = s4
```

### Step 4: 分配

每个样本归到最近的 medoid：

| 样本 | 到 s1 距离 | 到 s4 距离 | 归到 |
|:----:|:---------:|:---------:|:---:|
| s0 | 3 | 24 | **簇1** |
| s1 | **0** | 19 | **簇1** |
| s2 | 4 | 23 | **簇1** |
| s3 | 20 | **4** | **簇2** |
| s4 | 19 | **0** | **簇2** |
| s5 | 17 | 14 | **簇2** |

```
第1轮:
  簇1 = {s0, s1, s2}, medoid = s1, 总距离 = 3+0+4 = 7
  簇2 = {s3, s4, s5}, medoid = s4, 总距离 = 4+0+14 = 18
```

### Step 5: 更新 medoid

对每个簇，找总距离最小的点：

**簇1**: 计算每个点作为 medoid 时的总距离
- s0: dist(s0,s1)+dist(s0,s2) = 3+1 = 4
- s1: dist(s1,s0)+dist(s1,s2) = 3+4 = **7**
- s2: dist(s2,s0)+dist(s2,s1) = 1+4 = 5

→ s0 总距离最小(4)，成为新 medoid

**簇2**: 计算每个点
- s3: dist(s3,s4)+dist(s3,s5) = 4+15 = 19
- s4: dist(s4,s3)+dist(s4,s5) = 4+14 = **18**
- s5: dist(s5,s3)+dist(s5,s4) = 15+14 = 29

→ s4 保持不变

### Step 6: 重复直到收敛

```
第2轮:
  簇1 = {s0, s1, s2}, medoid = s0, 总距离 = 0+3+1 = 4
  簇2 = {s3, s4, s5}, medoid = s4, 总距离 = 4+0+14 = 18

第3轮: medoid 不变 → 收敛
```

### 最终结果

| 簇 | 样本 | Medoid | 中心模板（经过双压缩） | 判定厂商 |
|:--:|:----:|:------:|----------------------|:-------:|
| 1 | s0, s1, s2 | s0 | `[0,0,0,4,0,6,0,0,4,0,11,11,9,0,8]` | Roundcube |
| 2 | s3, s4, s5 | s4 | `[1,2,2,1,2,3,1,2,3,4]` | Zimbra |

## 两种算法什么时候用哪个？

```
你的数据是标准化后的文本？   → 贪心聚类（自动决定簇数）
你的数据是序列/编码/标签？ → K-Medoids（需 Elbow 法选 K）
簇数已知？                 → K-Medoids（省去 Elbow）
不知道有几个厂商？         → 贪心聚类（调 θ 控制粒度）
```

论文中用到了两种：
- **贪心聚类** → SMTP/SSH Banner 聚类（3.1.2 节）
- **K-Medoids** → Webmail DOM 序列聚类（3.2.3 节）
